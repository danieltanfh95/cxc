# Self-host port of the cxc compiler

Goal state. The ported cxc compiler, when fed `cards.cxc`, emits a byte-for-byte identical `cards.m` to the current Clojure compiler. `diff -q` returns clean. Not "equivalent", not "close", byte-for-byte.

Parity target. `compiler/self_host/parity_target/cards.cxc` in this repo (960 LOC, copied in at the local-to-cloud handoff from `/Users/danieltan/Projects/g-daniel/cards/dota2/cxc/cards.cxc`). Oracle output is `cards.m`, 1,496,605 bytes under the chapter-10 compiler state, 1,497,058 bytes post chapter-16 record-field retain fix. Current baseline sha `738b928dbcefbba251f5887133e6eef65b369c463ebecbe516a7dbec2b0f1707`.

## Layout

```
compiler/self_host/
  README.md                  # this file
  src/                       # cxc source for the ported layers
  oracle/                    # clj CLIs that invoke the live cxc.* modules
  corpus/                    # input fixtures each layer is tested against
  harness/                   # shell drivers that run both sides, diff output
```

Everything under this directory is net-new. The existing compiler tree stays untouched.

## Port strategy

Terminal from the bottom up. We port leaf layers first (pure functions, no AST entanglement) and build toward lower + emit. Each layer gets:

1. a cxc source port under `src/`
2. a clj oracle under `oracle/` that drives the live cxc.* namespace against stdin
3. a corpus under `corpus/`
4. a shell harness under `harness/` that compiles the cxc source, runs it against each corpus line, runs the oracle on the same corpus, and `diff -q`s the outputs

Byte-for-byte diff is the only accepted exit condition. If a layer's parity hinges on JVM-side nondeterminism (hash ordering, UUID, etc.) we canonicalise both sides and flag the canonicalisation step.

## cxc stdlib readiness audit (as of 2026-10-04)

What is in place.

- String: `+` concat, `.length`, `.contains`, `.starts_with`, `.ends_with`, `.substring(offset, length)`, `.index_of`, `.trim`, `.trim_prefix`, `.trim_suffix`, `.replace`, `.uppercase`, `.lowercase`, `.to_int_or`, `.to_bool_or`, `.repeat`, `.pad_left`, `.pad_right`, `.to_bytes`
- Bytes: `.at(offset) -> Int` byte-wise read
- List of T: `.append`, `.filter`, `.at`, `.count`, `.contains`, `.for_each`, `.sort_by`
- Set of T: `.insert`, `.without`, `.contains`, `.count`
- Map of T: `.assoc`, `.dissoc`, `.get`, `.at`, `.count`
- FileSystem cap: `read_text`, `write_text`, `read_bytes`, `write_bytes`, `exists`, `is_dir`, `is_file`, `mkdirs`, `remove`, `copy`, `rename`, `size`, `tmp_path`, `list_dir`
- Subprocess cap with explicit env, Args, Console (write/write_err/readln), EnvVars/EnvMut split
- `||:` multi-arm dispatch, `:-` observations, typed error raises

What is missing (blockers for later layers).

- String character-at. No `.at(i) -> Char` for String. Workaround for ASCII: `s.substring(i, 1) == " "` or convert to Bytes and byte-at. Unicode identifier scanning cannot be expressed without a code-point iterator.
- Character predicates. No `is_whitespace`, `is_digit`, `is_letter`, `is_hex_digit`, `is_unicode_identifier_start`. Implementable in pure cxc for ASCII; blocked for full UAX #31.
- Parse-int with base. `.to_int_or` is decimal-only. Hex, octal, binary literal scanning needs a base-N parser.
- String split. No `.split(sep) -> List of String`. Implementable in pure cxc on top of `.index_of` and `.substring`.
- Character ↔ integer code-point conversion. No `Char.code()`, no `String.from_code(n)`. Needed for escape-sequence handling (`\\u{HEX+}`).
- Line reading. `console.readln()` exists; no `fs.read_lines(path)`. Workaround: `fs.read_text(path).split("\n")` once split lands.
- No instaparse analogue. The current parse layer uses instaparse's grammar DSL. Porting parse means a hand-written recursive-descent walker.

What is NOT a blocker (verified in-scope).

- Set-of-String literal via `.insert` chaining is fine for small reserved-word sets.
- Positional argv access via `args.get_or(1, "")`.
- Shell-driven differential testing. Each run forks a cxc binary per corpus line and a single clj process for the oracle.

Compiler gaps discovered while landing chapter 2.

- `let x: T` where T is a primitive (Int, Bool, Float) stores x as `_Cxc_Optional_T` even when the RHS returns a raw non-nullable primitive. Reaching for the raw value inside a `substring` or `NSUInteger` cast then fails compile with "operand of type `_Cxc_Optional_Int64` where arithmetic or pointer type is required". Workaround is `let x: T!` for the non-nullable storage. The surface rule is in `corvid-nullability-rule` memory and the lesson is to type-annotate `T!` whenever you reach for a raw int inside an ObjC cast.
- Lambda bodies cannot span multiple statements and cannot bind locals via `let`. The lambda surface is `arg => expr`. Captures of outer `Int` locals widen even when the outer binding is `T!`, so the practical rule for now is to avoid capturing locals of primitive type in filter and map lambdas, or hoist them to atom fields.
- Multi-arm `||: ... ||: else : ...` chains do not continue across newlines. The parser errors with "expected an expression, got a newline". The whole chain must live on one physical line, or be hoisted into an observation body on one physical line. Long chains are the current workaround for the lambda-capture gap and lose readability past about 10 arms.

## Oracle convention

Each layer's oracle is a short `clj -M -e "..."` one-liner that requires the live cxc.* namespace, reads stdin line-by-line, calls the target function, writes `\n`-terminated stdout. The oracle NEVER mutates the live namespace. The oracle NEVER canonicalises unless the layer requires it (and the canonicalisation step is documented in that layer's section below).

## cxc program convention

Each layer's cxc port is a `def main:` program that reads one positional arg (`args.get_or(1, "")`), applies the ported function, writes the result with `console.write`. The shell harness invokes the binary N times (once per corpus line). This is intentionally slow but byte-stable.

- Reusable corpus-driven slice pattern. Each slice is a function with a stable scalar-input to scalar-output contract. For slices that need multi-row ambient state, pass the state as a file path in argv and read via `fs.read_text`. The cxc port and the clj oracle emit newline-terminated output on the same corpus, and the harness `diff -q`s the two output files. New slices follow the four-file shape (src, oracle, corpus, harness).
- Delimiter convention for multi-field corpora. Use `|` not `\t`. Bash `IFS=$'\t' read -r a b` collapses a leading tab, which turns `\tX` into `a=X b=""` instead of `a="" b=X`. The pipe is not a whitespace char so empty leading fields round-trip correctly. The two-arg glyph harness uses tab and happens to parity by coincidence (its empty-source rows have no match either way), the pipe is now the recommended delimiter for new slices.
- Idioms learned.
  - Always annotate primitive locals as `T!` (`let i: Int! = ...`) when the value will cross into an ObjC cast or substring index.
  - Avoid lambda capture of local Int bindings. Either inline the function with `||:` chains or hoist the local to an atom field.
  - Keep `||:` chains on one physical line even if long.
  - Use `args.get_or_int(index, fallback)` not `??`-coalesced int. `??` on a non-nullable primitive storage widens it back to Optional per the gap documented above.
  - `module` is a reserved keyword, use `mod_name` or similar.

- Substring safety under eager eval. cxc evaluates all `let` bindings eagerly. When a port uses `index_of` + `substring` to extract a sub-range on possible-miss inputs, the intermediate `substring(start, len)` call fires even on miss. If `len` goes negative, NSString raises an NSInvalidArgumentException and the program crashes. Clamp with `.max(0)` and `.min(input.length())` for every intermediate index / length, let the final `||: hit_idx == -1 : ...` short-circuit discard the garbage substring.

- Chapter 5 idiom learnings.
  - Terminal phase MUST be named `end`. Non-`end` terminal phase names (`emit`, `finish`, `done`, …) leave the atom idling in the dispatch runloop — `-transitionToEnd` is the only exit cascade. `then:` on a target=`end` transition is a compile error (spec §1.11), so error paths set an `error` flag and dispatch `self :> step`, letting a guard-only `<: step -> end |: error` arm fire on the next tick.
  - Multi-arm dispatch at the SAME phase on different message names coexist safely (`parsing <: step` and `parsing <: commit`), but single arms without `|:` guards may drop silently per F8 L3 dispatch rules; inline branch logic into guarded arms instead of relying on an unguarded fallthrough.
  - `||: cond : stmt-A ||: else : stmt-B` with statement-position bodies emits `emit-stmt: unknown node :c-ternary`. Compute via `let out: T! = ||: cond : A ||: else : B` and act on `out`; `||:` is an expression operator only.
  - `.code_at(i)` reads NSString unit widened to Int (ASCII-safe, matches the byte for 0 to 127). Out-of-range or nil receiver returns -1 so the sentinel composes with `||: at_end : -1 ||: else : …` observations without allocating NSData per tick.
- Chapter 6 idiom learnings.
  - `.compare_to(other)` returns strcmp-shape on UTF-8 bytes. Negative, 0, positive — the three guards an inline selection sort needs. Nil-tolerant: nil self sorts first, nil other sorts last. Use the chained-observation trick to extract the sort key (`scan_cur_name :- scan_cur.substring(0, scan_cur.index_of("|").max(0))`) before feeding `.compare_to`.
  - Field / observation names that collide with C-reserved words (`char`, `int`, `long`, `float`, `double`, `void`, `return`, …) emit as `self.<name>` at the C level and trigger `expected identifier` from clang, NOT a cxc-side error. Rename to a non-C-reserved synonym (`cur` for `char`, `len` for `int`, …) — the chapter-3 lesson about parser-reserved words (`module`) is distinct; this one bites at the emit boundary and surfaces as a clang error, not a cxc parse error.
  - Observations with chained `.at(index) ?? ""` for runtime list access work even when the index is temporarily out of range (e.g. a sentinel `scan_best_idx == -1`), because the `??` fallback short-circuits before any downstream substring call. Use `.max(0)` on index arithmetic that feeds `.substring` to keep intermediate values legal under cxc's eager let evaluation.
- Chapter 7 idiom learnings.
  - Enum case names cannot be cxc-reserved words. `case of` fails parse with `expected :ident got :kw "of"` (`of` is reserved per `cxc.lex/reserved-words`). Rename at the enum-definition site (`case parametric` for `:type-of`); the wire-level output tag can still spell `of:` if that matches the Clojure AST convention.

- Chapter 36 idiom learnings.
  - A recursive typer as a frame stack over the arena. infer-type recurses through binops, calls, dots, `do` blocks, and peer observables, with a context that changes on the way down. Each open node is a `Frame(n, st, a, b, c)` with its stage and two registers, `go` types the node at `cur` (a leaf answers at once), `rt` hands `val` to the frame on top, and a frame that changed the context saves the old one in `c` and restores it when it pops. An error is a value with a kind prefix (`!U:`, `!N:`, `!C:`) that unwinds every frame at once, which is how Clojure's first throw wins.
  - Read the env rows into the same arena. Slice 39's atom rows hold fields, defaults, and method bodies, too nested for text queries. Appending the rows to the stream before reading gives one arena, and the prep pass walks a row's `(fields ...)` and `(methods ...)` children like any other node.
  - Type keywords as their printed text. `{:record "Card"}`, `[:optional :int]`, and `[:int 32]` are queried with `starts_with` and cut with fixed offsets. The C type of a sized keyword follows from its text except SizeT and SsizeT, which carry their metadata as a `~size_t` mark that printing drops.
  - Read what the inference context leaves out. The pass builds its ctx without `:module-map`, so every `decl-lookup` misses and enum-case access, enum payload calls, and `Record.from` never match. Porting the branches that look reachable would have printed types where Clojure raises.
  - Deferred errors are a predicate on the message. try-infer-observation-body swallows three user-error shapes, so the port keeps the error kind next to the message and tests the same three patterns before it turns an error into a nil type.
  - Phases entered from many places get no on-enter. The pass phase is entered from prep, from the sort, and from the typer, so each entering arm sends its own first message, the chapter-35 lesson again.
  - The slice cache makes a pipeline harness cheap to rerun. Only the slice under test is cold after the first run.
- Chapter 35 idiom learnings.
  - Pipeline of small slices. A slice takes the printed output of the slices before it as input files and never copies their builders. The harness runs the earlier ports and cuts their output to the rows the next slice reads, and the port answers its questions with text queries on those rows (`\n(keep X)\n` for an atom-env key, the `(module m ...)` line for module-map membership, the `(decl X m)` line for the mangling module, an `(enum E ...)` row's payload-index for the enum-case defaults). Slice 40 has 84 fields and 87 arms and its `.m` is 5.0 MB, where adding the same builders to slice 39 would have cost about 370 KB per new writing arm. Each later slice of lower follows the same rule, input rows in, its own sections out, an earlier error passed through as one line.
  - What the `.m` costs. Every arm that stages a `=>` write commits every field of the atom (about 400 bytes of C per field), and every dispatch method snapshots every field once. A generated monolith of 80 fields and 80 writing arms emitted 2.80 MB, 40 by 40 emitted 0.85 MB, so the cost is fields times writing arms, and arms that only send or print add nearly nothing. The compiler's snapshot emit stays as it is (it would shift `cards.m`), so the port controls the cost at the source.
  - Splitting state across atoms. The same 80 fields and 80 arms split into a parent and a child atom (40 and 40 each) emitted 1.63 MB and printed the same result. The child is a field of the parent, starts on an explicit `c :> go()` that the parent sends once it has entered the phase holding its `wait <: c.finished(n: Int!) -> ...` arm, and emits `:> finished(...)` when done. Without the handshake the child's emit arrived while the parent was still in another phase and was dropped, and the program hung. A sub-slice of a big port (a reader, a mangler, a sort) can live in a child atom the same way, but a slice that is already small gains more from staying a separate slice.
  - Errors as values in a reduction. collect-shapes and canonical-named-tuple-name throw the first error in Clojure's own order (sorted fields first, outer checks before the inner). The stack scan reduces each construct when its `)` arrives, keeps an error as a token like any value, and each construct picks the first error in its own order, so one pass yields every shape name, every type's canonical name, and the first error postwalk would meet.
  - A phase entered from another phase re-runs its on-enter. A subroutine that returns into a loop phase (the named-tuple scan coming back from the shared sort) must not have an on-enter that restarts the loop, so those phases have none and each entering arm sends its first message itself.
  - `pkill -f <name>` matches the shell running it when the name is in the same command line. Kill by a pattern the command itself does not contain, as with `cxc[.]daemon`.

- Chapter 32 idiom learnings.
  - Rewrites as edits on the rendering. Every pass here changes a few nodes in a large tree, so the port never rebuilds the tree. The walk records `Edit(start, stop, text)` spans on the slice-36 text, a node that keeps some children (plugin.send keeps its receiver and later args) is two edits around the kept part, and the apply loop takes the edit with the least start at or after its cursor. - Chapter 31 idiom learnings.
  - Read a tree into an arena built at close. A node's subtree size is only known when it closes, so the reader appends each node then, with every field final, keeps the open lists on a slice-and-append stack, and sorts the arena by preorder index once at the end. Child one of node i is i + 1, the next sibling is i + size, and no node is ever rewritten, which matters because a record in a `List` cannot be updated in place.
  - A horizon for shallow consumers. The symbol table needs only depth three of the tree (program, declaration, item, item head), so the reader skips arena entries below that and deep subtrees still print through their kept ancestor's span. On the largest sweep file (a 90 KB rendering) that is 1.3 seconds against 7 seconds for the full arena, which refs mode needs.
  - Print members as spans, serialize them once. Every member in a table row is the verbatim slice-36 text of that node, and the oracle loads the slice-36 oracle's serializers with `load-string` instead of copying them, so the two layers cannot drift and a later layer can read a row back with the same reader.

- Chapter 26 idiom learnings.
  - Long `and` / `or` chains cost 2^N in the emit. The Kleene lowering of `a and b` binds `__typeof__(L) __cxc_kl = (L)`, so the left operand's C text appears twice and a left-nested chain doubles per term. The slice-33 unexpected-char guard grew from 18 to 31 negated terms and the compiler ran out of JVM heap emitting it (at 18 terms the `.m` was already about 64 MB). Grouping the char classes into five-term observations (`lex_known_a` to `lex_known_f`, joined by `lex_known`) fixed it, because observations lower to methods and a guard that calls them costs one call per term. Keep any guard or observation chain to about six terms. A compiler fix is queued as a separate task.
  - Call frames as records. Earlier stacks used parallel `List of Int!` or `List of String!`. A parse frame needs eight values, so it is a record `Frame` in a `List of Frame`, read through a `top` observation and rewritten through a parametric `retop(...)` observation that copies `kind` and `prec` from the current top and takes the other six fields. Record-valued parametric observations compile, and the chapter-16 retain fix plus the Linux box shim keep the string fields alive.
  - Precedence climbing as frames. A binop frame holds its min-prec, its lhs, and a pending op. An operator at or above the min-prec records itself and pushes a fresh binop frame at prec + 1. A frame whose next token falls below its min-prec pops and returns its lhs, and the frame below folds it in as the rhs. That is `(parse-binop tokens rhs-pos (inc prec))` one to one, so left associativity needs no extra rule and the tree matches Clojure's exactly.
  - Return-mode messages. The fifth use of the chapter-20 sentinel idiom, now carried by message names. `ret` dispatches on the kind of the frame below, so one arm set serves binop rhs, parenthesized group, call arg, subscript index, list item, lambda body, and `||:` guard and body. Every push goes through `frames.slice(0, depth).append(...)`, a pop is `depth => depth - 1`, so dead frames past `depth` never leak.
  - Desugar while building. The chained-comparison postwalk is bottom-up, so it can run at construction time. Each value carries a kind (`cmp`, `chain`, `other`) plus its op list and operand list, and folding a comparison over a `cmp` or `chain` lhs extends the chain. Parentheses keep the kind, as the AST does, so `(a < b) < c` chains and `a < (b < c)` does not.
  - parse-expression does not desugar. Only `cxc.parse/parse` runs `desugar-chained-comparisons`, so the oracle applies the private var to the parse-expression result. That is the tree an expression gets inside a real program, which is what the later lower port will consume.
  - Bracket continuation moves the eof line. Clojure bumps the line for every physical line whether or not it emits NEWLINE, so `f(a,` reports `got :eof nil at line 2` with no NEWLINE token at all. The shared lex used to key the final line bump on the last token, which fails once brackets suppress NEWLINE. The bump now keys on `at_line_start` (`ends_open_line`) and the NEWLINE on `eol_newline`.

The corpus keeps 45 expressions and 25 soup rows from that run, the chapter-25 pattern for pinning a large input space.
- Chapter 25 idiom learnings.
  - Render where the reference renders. The Clojure compiler never keeps float literal text. `cxc.lex` parses it to a Double and `cxc.emit/emit-expr` writes `(str (:value node))` into the `.m`, so the oracles print `Double.toString` too. Recovering the literal in the oracles (the chapter-11 pattern) would have kept parity today and left the later emit port with nothing. The port therefore carries the rendered `Double.toString` text in Token.value, and slice 34 pins the renderer against `(str (Double/parseDouble lit))` on its own corpus.
  - Shortest round-trip without a Double. JDK 19 and later print the shortest decimal that rounds back to the same double. Any decimal with at most 15 significant digits round-trips, so for such a literal in the normal range no shorter decimal maps to the same double, and the literal's own significant digits are the answer. The renderer only strips leading and trailing zeros, computes the scientific exponent, and applies Java's layout (plain for 1e-3 up to 1e7 with at least one fractional digit, `d.dddE<n>` elsewhere). A round-trip check through `.to_double_or` was the other route, but GNUstep's `NSScanner scanDouble:` builds the value from a truncated 18-digit mantissa and a power table, so it is not correctly rounded on Linux and cannot arbitrate the 16 and 17 digit cases.

The port has one `scan_digs` arm set with the three `_` errors and one `digs_done` dispatch keyed on `num_mode` (`int`, `frac`, `exp`, `based`, `hexfrac`), the fourth use of the chapter-20 sentinel idiom. Physical newline counts as end of run so `1_` at a line end reports `ends with` rather than `has trailing`.
  - Column inside indent-stripped content. The unit-suffix message quotes `col`, which Clojure counts within the indent-stripped line. The layout slice already tracks that as `col_num`. The parse layer has no column, so it records `line_content_sc` when indent measurement ends and derives `cur_col` from it. A `cur_col` observation in both files keeps the shared arms textually identical apart from column bumps.

- Chapter 23 idiom learnings.
  - Decode plus re-encode beats preserve-literal once the escape set grows. Chapter 22 stored the two-char `\<marker>` form in Token.value and relied on pr-str re-encoding the decoded byte to the same text. That holds only for escapes pr-str also prints escaped, so `\'` (pr-str prints a bare apostrophe) diffed and `\xNN` / `\u{...}` were unrepresentable. Chapter 23 decodes every escape to its code point and re-encodes through `enc(c: Int!) :- String!`, a parametric observation porting Clojure's `char-escape-string` table (newline, tab, return, double quote, backslash, formfeed, backspace escaped, everything else raw). Plain body chars route through `enc` too, so a raw tab in a literal prints `\t` the way pr-str does. The chapter-22 claim that pr-str emits `\uNNNN` for control bytes was wrong, Clojure's printer only escapes those seven chars.
  - Supplementary code points as a surrogate pair. `Int.to_char_string()` truncates to one unichar, so `enc` splits code points above U+FFFF into `(55296 + (c - 65536) / 1024)` and `(56320 + (c - 65536) % 1024)` and concatenates the two one-unit strings. NSString joins them into a valid pair and `UTF8String` emits the four-byte form, byte-equal to the JVM's UTF-8 stdout. `/` and `%` on `Int!` work in observation bodies.

Same shape as chapter 20 `nt_return_mode` and chapter 22 `container_return_mode`, third use of the idiom.

On `"\x4"` this re-entered a string and overwrote the message, and on `"\u{12G4}"` the stray `}` hit the unexpected-char arm, which re-raised forever, apparently because the first matching arm wins and it is declared before the `-> end |: error` arm.   - Clojure's lex is per physical line. Escape arms treat a physical newline as end of input (`at_src_end or is_nl`), matching the per-line `n` bound in `scan-string` / `scan-char`, so `"abc\` at a line end reports `trailing backslash in string` rather than an escape error on the newline.
  - Corpus sentinel for in-literal backslash-n. The three oracles that expand corpus newlines and both lex-site ports rewrite corpus `\n` to a physical newline, then rewrite `\N` to the two chars backslash-n. `\N` is never legal cxc source, so no existing row changes meaning. This retires the chapter-22 `\n` exclusion without rewriting the 120 rows that use `\n` for layout.
  - Error precedence follows Clojure's scan order. `\u{...}` reads every hex digit up to `}` before checking the 1 to 6 digit count, then the U+10FFFF ceiling. The port accumulates `esc_hex` / `esc_val` the same way (value accumulation freezes past 7 digits so a long body cannot overflow) and orders the `}` arms count-first, ceiling-second.

- Chapter 21 idiom learnings.
  - Inside-out substitution over a flat string. For a nested grammar `TNT(TNT(TNT(...)))` where leaves need conversion first and parents consume the converted leaves, the port rewrites the spec in place rather than building a parallel AST. Each outer loop finds the leftmost innermost occurrence (nest with no inner nest), converts its body, slices `spec = prefix + converted + suffix`, resets `pos => 0`, and re-scans. The outer loop terminates when `scanning` reaches `spec_end` without finding another `TNT(`. The alternative would be a recursive-descent walker over the pre-parse-layer AST — but the bridge consumes the parse-layer's string serialization by design, so a string rewriter composes with the existing chain. Stack-free, cxc-friendly, and the leftmost-innermost scan ordering guarantees progress.
  - Phase-reentry on-enter guards. Chapter-18 lesson about on-enter firing on different-phase transitions re-applies at the top-level driver. The chapter-21 bridge was initially written with `scanning`'s on-enter unconditionally seeding `spec => args.get_or(1, "")`. Each `substituting → scanning` return re-fired the on-enter and clobbered the just-modified spec, infinite-looping on the first TNT. Fix: a `once_init: Bool!` guard with ternary `spec => ||: once_init : spec ||: else : args.get_or(1, "")` so the on-enter is a no-op after the first entry. - Chapter 18 idiom learnings.
  - Slice-and-append stack discipline for a logical-size `List of Int!`. cxc `List` lacks `.pop` / `.drop_last` and lacks an index-aware `.filter`, so a stack machine built on an append-only list suffers a dead-value leak when a sibling frame pushes-then-pops at depth D and the next push at depth D places the new value at index D (list.count), not at index D-1 (where `at(depth - 1)` reads). The fix is `rem_stack.slice(0, depth).append(new)` on every push: slice to the active window, then append. Dead values beyond the slice are discarded automatically. Pop stays implicit (depth decrement only); the next push will slice-truncate before it writes. Verified against `Nt2_x_Nt1_y_Int_z_Nt2_a_Int_b_String` where the pre-fix output was `_Cxc_NT_x_Nt1_y_Int_z_Nt2_a_Int_b_String,_Cxc_NT_y_Int,_Cxc_NT_y_Int_z_Nt2_a_Int` (the `start_stack` dead value at index 1 leaked into the second nested frame's start-pos).
  - Snapshot semantics make stack-top-after-decrement read the right saved slot. On pop, `top_consumed => saved_consumed.at((depth - 1).max(0)) + 1` reads `depth` as the OLD value (snapshot), so `depth - 1` equals the new-depth-index of the parent's saved value. Writing `depth => depth - 1` in the same arm doesn't interfere because the stage happens at arm end. This is why observations like `top_rem :- rem_stack.at((depth - 1).max(0)) ?? 0` can live outside the arm and still line up with the active frame after a push or pop.
  - Observations chained over mutable state as a parse-ahead probe. Testing whether the type at a scan position is `Nt<digits>_` requires looking past the fname separator, past any `Nn_` prefix, then checking three byte codes. Encoding this in guards would duplicate work across arms. Instead, a chain of observations (`fname_sep_at_pos` → `after_fname_at_pos` → `type_rest_at_pos` → `is_nn_at_pos` → `type_body_at_pos` → `type_is_nt`) factors it once and the guards reference `type_is_nt` directly. - Chapter 13 idiom learnings.
  - Clojure fail! format for byte-level parity. `cxc.parse/fail!` throws with message `"parse error: <msg> (got <kind> <pr-str value> at line <line>)"` where kind is a `:ident`-style keyword and pr-str on string values adds `"..."` quotes, nil values print `nil`. For a cxc port that drives the oracle on erroneous inputs, lower every layout-marker kind to the Clojure spelling (`newline` / `indent` / `dedent` / `eof`), emit `"` around content token values, emit bare `nil` for layout tokens, and reuse Clojure's own context-shortened messages (`expected :ident`, `expected :punct ":"`, `expected :kw "import"`, `expected top-level form`) rather than inventing richer phrasings.
  - Trailing-newline convention of Clojure lex. `cxc.lex/tokenize` ALWAYS appends a terminal `:newline` token after the last content on the last source line (even when the physical source has no trailing `\n`), then advances the line counter, then emits any trailing `:dedent` tokens, then `:eof`. This makes error messages for `def X:` report `(got :eof nil at line 2)` even though the source is one physical line. A cxc port that elides the trailing newline will mismatch line numbers for all errors whose cur-token is the trailing EOF.
  - Column reset after INDENT. Clojure lex's column attribute is 1-based within the indented content, not the absolute character position. A line like `    name: String!` reports `name` at col 1, `:` at col 5, `String` at col 7, `!` at col 13 — the leading four spaces are absorbed by the INDENT token (which itself has col 1). A cxc port that tracks absolute char position will mismatch columns on every indented line; the fix is to reset `col_num => 1` in the measure_indent → adjust_indent transition before any content token's col gets stamped.
  - Observation reference ordering. An observation body `a :- b` where `b` is also an observation requires `b` to be lowered first; otherwise clang emits "lowering not yet implemented: type-of identifier `b` (no local-binding env yet)". Reorder observations so observations referenced by other observations are declared earlier in the atom body (this is a stable, lexical dependency, matches the chapter-10 fallthrough-coverage discipline).
